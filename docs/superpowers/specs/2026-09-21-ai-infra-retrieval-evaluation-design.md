# AI-Infra 检索评测与高频漏召回修复设计

日期：2026-09-21  
状态：已确认，等待规格审阅

## 目标

为个人知识库的《AI-Infra-Book.pdf》建立可重复执行的检索评测基准，衡量“学习时理解、总结书中概念”场景下的证据召回质量。基准应能定位漏召回发生在切分、向量召回、缩写精确匹配、重排或证据截断的哪个环节，并将确认的高频故障固化为自动回归测试。

本阶段的重点是资料证据是否进入最终回答上下文，而不是语言模型的文采或通用知识正确性。

## 范围与非目标

### 范围

- 只评测本机已上传的《AI-Infra-Book.pdf》。评测集绑定该文档的内容哈希，避免文件替换后沿用失效的预期答案。
- 建立 25 道中文学习题，覆盖基础定义、机制链路、概念对比、章节总结、英文缩写和资料不足六类。
- 为每道题维护预期关键页码或定位锚点、关键术语和必须覆盖的概念。
- 运行真实的现有检索链路，保留向量候选、精确缩写命中、重排结果与最终 6 条证据的诊断信息。
- 对确认的高频漏召回实施最小修复并前后对比；对应故障题加入轻量自动回归测试。
- 提供可选回答生成评测，人工记录解释清楚度和引用贴切度。

### 非目标

- 不评测示例 Markdown、英文版 MambaIRv2 或重复上传的论文。
- 不在本阶段新建前端页面或评测 UI。
- 不替换 Embedding 模型、不接入联网检索、不迁移向量数据库。
- 不承诺所有题目均能回答正确；每个失败题必须能归因或明确标为待研究。

## 评测集

评测集作为版本控制的结构化数据保存。每条记录包含：

- 稳定题目 ID、中文问题、题型；
- 目标文档内容哈希；
- 预期页码或片段定位、关键词和必须覆盖概念；
- 对资料不足题的明确标记与其拒答预期；
- 人工评分字段的模板，但不保存 API 密钥、完整回答或用户会话内容。

题目由实现方依据该书目录和正文初拟，覆盖“模型与负载”“芯片与系统”“推理与训练系统”三部分；用户随后可审阅、删除、改写或补充题目。预期证据不要求逐字相同：只要最终证据足以支持该题的核心解释，即视为召回命中。

## 运行流程

评测脚本读取评测集，确认目标 PDF 存在、内容哈希一致、索引状态为 `ready` 且当前向量配置指纹匹配。随后逐题调用 `Engine.retrieve`，并将以下数据写入 Git 忽略的结果报告：

1. 向量候选及其排名和相似度；
2. 精确缩写匹配候选；
3. 重排服务状态、得分、回退原因；
4. 最终被选入的最多 6 条证据；
5. 自动命中判定、未命中原因提示和汇总指标。

自动判定以预期页码/定位锚点或关键术语进入最终证据为基础。结果报告同时保留原始诊断，以便人工修正自动判定无法覆盖的语义等价证据。

脚本默认只执行检索，不调用外部回答服务。显式启用“含回答”模式时，按现有问答约束把问题和检索到的少量证据发送至当前配置的 Chat Completions 服务，报告保存回答、引用编号以及待人工填写的“解释清楚度”和“引用贴切度”。该模式会产生服务费用，且不发送整本 PDF。

若前提不成立（PDF 缺失或已替换、未就绪索引、配置指纹不符、模型不可用），脚本应以明确错误退出，不能将其计为低分或漏召回。

## 漏召回诊断与修复策略

每个失败题按以下顺序诊断：

1. 解析和切分：关键内容是否存在于 SQLite 片段，片段是否截断语义；
2. 候选召回：关键片段是否进入向量候选或精确术语候选；
3. 排序：关键片段是否因重排被排出有效证据；
4. 证据组装：关键片段是否进入候选却没有进入最终 6 条；
5. 回答：检索已命中时，回答是否仍未解释或引用错误。

修复遵循最小变更原则：只针对评测确证的瓶颈调整相应层，例如同义词/别名扩展、相邻片段补全、候选数或证据保留策略。修复不得降低既有 MHA 缩写检索回归，并需通过完整评测集前后比较。

## 验收与测试

首轮输出包含：

- 25 题的检索命中率，以及按题型分组的命中率；
- 每题最终证据和层级诊断；
- 可选回答模式下的人工质量记录；
- 修复前后的指标差异和剩余失败项清单。

普通后端单元测试继续使用可控的小型 fixture，不依赖真实 PDF、模型下载或外部 API。确认的高频漏召回题将抽取出快速、确定性的回归测试，覆盖其关键检索决策。完整 AI-Infra 评测作为本机手动或发布前检查运行，不纳入每次 `pytest` 的默认路径。

## 成功标准

- 评测集有 25 道符合学习理解/总结目标的中文题，且只引用 AI-Infra 文档。
- 报告能区分候选召回、排序和最终证据组装的失败。
- 默认评测可离线于 Chat 服务重复执行；回答生成必须显式选择。
- 高优先级、可复现的漏召回得到修复并有自动回归保护。
- 用户可根据报告判断检索是否足以支撑概念解释与章节总结。
