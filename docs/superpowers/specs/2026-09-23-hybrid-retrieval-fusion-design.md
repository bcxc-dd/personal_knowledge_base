# 双路混合检索与证据融合设计

## 目标

将现有“向量主召回、词法补召回”的隐式策略改为可解释的双路融合检索。重要的术语正文即使未进入向量 Top-K，也能作为最终证据；目录、标题、参考文献和泛化词命中不能据此作答。

## 架构

每个问题独立执行向量 Top-K 和词法 Top-K：

`向量召回 + 词法召回 -> RRF 融合 -> 可选 reranker -> 最终证据 -> 充分度判定 -> 回答`

候选不再通过替换规则互相挤出。合并后的同一片段保留以下字段：

- `vector_rank`、`vector_similarity`：仅向量路径存在；缺失值为 `null`，绝不表示 0。
- `lexical_rank`、`lexical_score`：仅词法路径存在。
- `retrieval_sources`：`vector`、`lexical` 或两者。
- `fused_rank`、`fused_score`：RRF 融合结果。

RRF 默认常数为 `k=60`，分数为每条可用路径的 `1 / (60 + rank)` 之和。候选按融合分数排序。启用 reranker 时仅重排融合候选；reranker 回退时保留 RRF 顺序。

## 词法证据分层

词法命中分为三个层级：

1. 候选：命中受控中文术语、英文技术短语或缩写，可进入融合。
2. 可用证据：命中实质性正文，排除目录、标题、参考文献和仅有泛化词的片段。
3. 充分支持：正文能直接回答一个独立核心子问题。

直接定义、机制说明或明确关系可以构成实质性正文。一个多约束问题不能因只命中其中一个泛化词而被判支持；缩写定义问题可以由目标缩写在解释正文中的明确出现支撑。

## 充分度判定

判定器对最终融合证据逐一评估核心子问题：

- 所有核心子问题有充分支持：`supported`。
- 至少一个充分支持、至少一个不足：`partial`。
- 没有充分支持：`insufficient`。

判定器不以是否具备 `vector_similarity` 作为必要条件。词法直接证据可以独立支持回答；`vector_similarity=null` 表示该证据没有由向量路径召回。

“预填充和解码分别做什么？”的第 14 页同时解释预填充处理输入、解码逐步生成 token，必须支持两个子问题并判为 `supported`。q23 的 GPU 片段没有支持“特定公司内部集群的精确数量”，必须保持 `insufficient`。

## 前端诊断

检索诊断面板按三个区域展示：

- 向量候选：显示向量排名和相似度。
- 术语候选：显示词法排名和命中分数。
- 最终回答证据：显示来源、融合排名、融合分数及是否用于回答。

第 14 页一类证据必须能显示为“术语候选 -> 最终回答证据”，而非因没有向量分数而消失。

## 验收与评测

- q04 必须为 `supported`，且第 14 页出现在最终回答证据。
- q23、q24、q25 必须为 `insufficient`。
- 20 道 AI Infra 自动正例不能出现错误拒答。
- 评测报告记录 RRF 常数、候选来源、三类指标与阈值。
- 回归测试覆盖单路词法直接证据、双路命中、目录式词法命中、单个泛化词命中和 reranker 回退。
