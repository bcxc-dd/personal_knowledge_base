# 本地重排与复习笔记设计

日期：2026-09-19  
状态：待用户评审  
适用版本：MVP 后续版本

## 1. 目标与边界

本版本同时改善“查资料”和“学知识”两种体验：

1. 在现有向量召回之后增加本地重排，验证候选片段是否能更准确地支持回答。
2. 在回答旁增加可编辑复习笔记，保留来源定位，供用户阅读和复习。

复习笔记是独立内容，只用于阅读和复习。笔记不会写入 Chroma，不参与文档检索，不作为回答证据，也不会改变原始资料的可信边界。

本版本不包含关键词混合检索、OCR、文档版本历史、标签体系、双向链接、复习卡片、自动摘要和多设备同步。

本版本增加检索过程的可视化诊断，但不把它设计成面向普通阅读的复杂分析面板。可视化服务于调试和理解：用户可以看到一次问题的候选片段、向量相似度、重排分数和最终是否进入回答证据。

## 2. 查资料：本地重排流程

现有流程为：问题向量化 → Chroma 召回 → 将结果交给回答模型。本版本改为：

```text
问题
  -> 向量召回候选（默认 20）
  -> 本地重排模型对“问题 + 片段”评分
  -> 按分数排序并截取最终证据（默认 6）
  -> 回答模型生成带引用的回答
```

候选数和最终证据数应作为后端配置项，初始值分别为 20 和 6，便于用真实问题集调整。重排只影响本次查询，不修改持久化向量和原始片段。

本地重排模型通过独立适配层加载，优先使用 CUDA；CUDA 不可用时允许使用 CPU。模型首次加载、显存不足、依赖缺失或推理异常时，接口应返回可理解的状态信息。单次重排失败时回退到现有向量检索结果，回答流程仍可继续；回退状态要在回答元数据中标记，便于验证时区分两种路径。

设置页应展示重排是否启用、模型是否可用、当前设备（GPU/CPU）和最近一次失败原因。问答页不强制用户理解模型细节，但在来源区域可以显示“已重排”或“使用向量召回结果”。

回答提示词和引用校验规则保持现有约束：模型只能根据最终证据回答，引用编号必须对应最终来源，证据不足时明确说明。

## 3. 学知识：复习笔记

回答完成后提供“保存为笔记”操作。保存时默认带入：

- 自动生成的可编辑标题；
- 用户问题；
- 完整回答正文；
- 保存时间；
- 引用来源的文档、位置和片段快照。

笔记详情页允许修改标题和正文，删除笔记，并从引用跳转到文档详情中的对应位置。引用快照保留回答当时的证据，即使原文后来被删除，笔记仍能显示“来源已删除”状态；不能把已删除来源伪装成当前可检索资料。

笔记列表至少支持按标题和更新时间浏览。首版不要求富文本编辑器，沿用 Markdown 文本即可；渲染时复用现有 Markdown 展示能力。

笔记使用 SQLite 独立表和引用关联数据保存，不复用 documents、chunks 或 Chroma 的生命周期。删除笔记不会删除原始文档、会话或向量。

## 4. 数据流与接口边界

检索层新增一个 `Reranker` 接口，输入问题和候选片段，输出带分数的候选列表。`Engine.retrieve` 负责召回、调用重排器、截取最终结果，并返回检索路径和失败回退信息；回答层只消费最终结果，不直接了解模型实现。

笔记层新增独立的创建、查询、更新、删除接口。创建接口接收会话消息和引用数据的稳定快照，避免只保存会话消息 ID 后无法恢复历史来源。前端在回答完成后才允许保存，流式回答中和回答失败时不显示保存成功状态。

## 5. 检索相似度可视化

问答完成后，在来源区域增加一个可展开的“检索分析”视图。默认保持收起，避免干扰正常阅读；展开后展示本次查询的检索链路：

```text
候选片段（最多 20）
  -> 向量相似度排序
  -> 本地重排分数排序
  -> 最终证据（最多 6）
```

每个候选片段显示：文档名称、位置、向量相似度、重排分数（若启用）、最终排名，以及“入选/未入选”状态。使用横向条形图或点图表达分数，分数旁显示原始数值；不同分数不可直接混用，界面应明确标注“向量相似度”和“重排分数”是两个不同指标。

可视化至少支持按向量排名、重排排名和最终状态排序，并允许点击片段查看原文。最终进入回答的片段使用强调色，未进入的片段保持弱化显示。若发生 CPU 回退或重排失败，图表顶部显示检索路径说明，而不是伪造重排分数。

后端在问答的来源元数据中返回本次查询的诊断信息，但不保存完整候选正文到会话历史；只保存文档 ID、片段 ID、定位、分数和是否入选。这样可以复现一次查询的排序结果，同时控制数据库体积。分数仅用于相对比较和调试，不在界面上解释为“答案正确率”或概率。

验证时增加三项检查：向量排序与实际 Chroma 结果一致；重排排序与最终证据一致；关闭重排或发生回退时，可视化明确反映实际路径。

## 6. 错误处理与资源控制

- 重排模型加载失败：标记不可用，回退到向量召回，并给出设置页可查看的原因。
- 显存不足：降低批量大小后重试一次；仍失败则切换 CPU 或回退。
- GPU 被其他程序占用：不阻塞上传和已有问答，状态显示为 CPU 或回退。
- 服务重启：重排模型按需加载，不要求启动时占满显存。
- 候选片段过长：沿用现有片段上限，必要时在重排适配层进一步截断，不改变存储正文。

## 7. 验证方式

使用个人资料建立一组约 15～20 个问题，覆盖：直接事实、同义改写、跨段信息、跨文档信息和资料中没有答案的问题。对同一问题分别运行“仅向量召回”和“向量召回 + 重排”，记录：

- 支持正确答案的片段是否进入最终证据；
- 无关片段比例；
- 回答引用是否正确且完整；
- 重排耗时、显存占用和 CPU 回退次数；
- 证据不足问题是否仍能拒答。

验收不要求重排在所有问题上都优于基线，而要求结果可比较、失败可回退、性能开销可见。复习笔记验收包括创建、编辑、删除、引用跳转、已删除来源提示，以及笔记不参与检索的回归测试。

## 8. 建议的实现顺序

1. 抽象重排接口和配置，保留当前向量检索作为基线。
2. 接入本地 CUDA/CPU 重排实现和回退状态。
3. 扩展检索测试与真实问题对比记录。
4. 增加笔记数据模型和后端接口。
5. 返回检索诊断元数据并增加相似度可视化。
6. 增加回答保存、笔记列表和编辑详情界面。
7. 运行后端、前端、构建和本地模型验证。
