# Chroma RAG MVP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 用户上传资料后自动处理，并可通过真实模型检索问答、查看来源。

**Architecture:** React 前端与 FastAPI 本地服务；SQLite 保存状态、配置与会话，Chroma 保存向量。一个服务进程中的后台线程消费持久文档任务，Chroma 访问加锁；避免多进程同时打开嵌入式存储。

**Tech Stack:** React / TypeScript / Vite / SCSS Modules / FastAPI / SQLite / Chroma / httpx / pypdf / python-docx.

**Spec:** `docs/personal-knowledge-base-plan.md` v0.2；用户本轮明确要求据此实现 MVP，直接在当前会话执行。

## Global Constraints

- `src/app.tsx` 仅路由配置，使用 config 对象。
- 页面与页面内部组件必须包含独立 index.tsx、hooks、style 目录。
- 本地单人运行，不开放公网；不实现账号、OCR、混合搜索、笔记编辑或 pgvector。
- 模型从本地设置页配置；不编造模型回答，不在日志或配置读取接口返回密钥。
- 支持 TXT、Markdown、文本 PDF、DOCX；最大 20 MB；持久化、重复检测、重试与删除。
- 支持知识库与文档检索范围、流式回答、引用、会话、备份恢复说明。

## Review Focus

- 无模型时上传仍可解析；配置后可继续向量化。
- 删除中途的文档不能被任务重新发布，也不能进入后续检索。
- 切换 Embedding 模型不能查询旧模型空间；可重建文档索引。
- 上游失败、空正文、错误向量维度、未知引用不能呈现成功答案。
- 中文长文、PDF 页码、跨知识库过滤、服务重启需要保留正确状态。

## Execution decisions

- Workspace initially contains only documentation and is not a Git repository; build in `D:\rag` without creating an unrelated worktree or committing on the user's behalf.
- Single-process embedded worker replaces separate process for this MVP, preserving durable task state while avoiding competing Chroma clients. Production scaling remains a separate milestone.
- Initial splitting uses character bounds and paragraph boundaries rather than a model-specific tokenizer; document this approximation and keep chunking configurable in code.
