# q05/q15：按问题覆盖组装证据的有界上限验证

日期：2026-09-26。目的不是宣称已实现自动选证，而是先验证：如果**不改变向量/词法召回与 RRF**、只把必要正文补到回答证据中，q05/q15 的实际回答是否改善，以及补充证据的来源边界在哪里。实验只读取 [前次 25 题完整报告](2026-09-25-ai-infra-chapter-context-review.md)对应的本机原始结果和同哈希资料，未修改正常问答代码或用户会话。

## 方法

实验脚本 [probe_coverage_upper_bound.py](../../scripts/probe_coverage_upper_bound.py) 是**金标准引导的上限实验**：人工指定待补片段，由脚本核对它确在当前同一文档的已有候选/章节上下文中；若不在候选中，仅允许已入候选片段的同页相邻片段。每个变体最多增加两个片段。用与当前问答链路相同的回答提示，在当前已配置的 DeepSeek Flash 服务上成对生成；结果文本、证据和耗时保存在被 Git 忽略的 `test-results/ai-infra-coverage-upper-bound-pair-20260926.json`。它**没有**自动判断缺失子问题、没有自动找到片段，也没有接入产品。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/probe_coverage_upper_bound.py --baseline test-results/ai-infra-v2-chapter-context-answer-final-20260925.json --data-dir data --output test-results/ai-infra-coverage-upper-bound-pair-20260926.json
```

文档 SHA256 为 `cdbb925efe420ab0c65a245068770e443b4f52995e902c56669324329725e217`，本地分支 `master`，提交基线 `5bee8c3` 加尚未提交的工作区改动。脚本不会输出密钥。回答内容受模型采样影响，本次是一次成对观察，不是稳定通过率或延迟基准。更早的两次上限试跑分别留在 `test-results/ai-infra-coverage-upper-bound-20260926.json` 与 `test-results/ai-infra-coverage-upper-bound-neighbor-20260926.json`，下表以最后一轮为准。

由于实验代码完全不接入 `Engine`，其余 23 题的实验输入按定义保持基线；这**不是** 23 道生成答案的重新人工验收。另用原运行器在同一资料上重跑 25 题、不调用生成模型，原始文件为 `test-results/ai-infra-v2-coverage-probe-unchanged-20260926.json`：25/25 判定状态仍为 22 `supported`、3 `insufficient`，6/6 受控 fixture 匹配，25/25 真正送答的片段 ID 与上一份完整报告一致。向量候选尾部在 q05/q23/q24 出现少量变化，q24 的第六个融合片段也变化，但没有改变送答证据；因此不能说每一路候选逐字完全稳定。重排仍 25/25 回退 RRF。

工程回归最终 `pytest -q` 为 78 通过、2 条既有依赖弃用警告。两个脚本合计新增 11 个测试，先看到针对证据来源、最多两片、同页限制、引用与盲选 ID 校验的预期失败，再实现实验逻辑。未修改产品问答、索引或前端，**不需要重启、重新构建或重建索引**。未进行前端用户复测。

## 无金标准盲选对照

上限实验之后，又试了一版**未接入产品**的盲选器：[probe_coverage_blind.py](../../scripts/probe_coverage_blind.py)。它只看到问题、实际送答片段、原前 20 候选、最多三个现有章节上下文，以及前 20 中词法前 10 片段的同页邻片；不含题号对应的正确页码和金标准。让现有回答模型从中最多选两片，严格校验返回 ID 必须来自候选池。只试 q05/q15 及 q04/q18/q23/q24/q25 五个对照题；原始选择和生成文本在本机忽略的 `test-results/ai-infra-coverage-blind-20260926.json`，并非 25 题盲选准确率。

这说明“补对证据时能答好”与“能可靠自动选对证据”是两回事。盲选器还缺少已送答去重、澄清优先门控、章节结构覆盖与真实事实充分度判断；现有提示词并不能可靠补齐这些缺陷。虽然本轮单次选择调用仅记录约 0.4–0.8 秒，但样本很小，不能当成稳定延迟基准，且提示有约 8–18 千字符的额外输入成本。**此版本不得直接上线。**

## 结论与下一步

本轮支持“按核心问题覆盖组装证据”作为研究方向，但**不支持直接上线任何本轮结果**：人工上限能补齐核心事实，自动盲选却在 q15 和澄清反例上失败。q05 也显示仅重排现有候选不够，最贴切的条件说明需从已命中的第 40 页片段向前做有界同页扩展。下一步不应继续调提示词来追两道已知题；应先明确可验证的选择契约（澄清优先、已送答去重、章节结构与事实覆盖、同页邻接界限），准备不同表述与负例，再比较确定性结构规则、小模型/交叉编码器或模型判定是否真能稳定满足契约。通过盲测和完整题集回归后才考虑接入实际问答；同时独立处理“本次片段”与“整书资料”混淆的生成约束。
